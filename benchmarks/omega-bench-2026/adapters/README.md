# Contrat des adaptateurs

Chaque adaptateur lit uniquement les entrées candidates et écrit le schéma `schemas/result.schema.json`. Par défaut, les entrées viennent de `dataset/public/inputs/<E>.jsonl`; `OMEGA_DATASET_ROOT` et `OMEGA_DATASET_INPUTS` permettent d'injecter un jeu préparé par l'assesseur. L'adaptateur reçoit `scenario_id`, `experiment_id`, `seed` et `input`; il ne reçoit jamais l'oracle. Les permissions, versions, paramètres du modèle, budget et matériel doivent être consignés dans un manifeste d'exécution.

Familles comparées : MLIR (représentation/validation), Temporal (durabilité/replay), LangGraph (graphe/checkpoint), A2A (délégation), MCP (invocation typée), OPA (décision de politique) et JSON Schema + exécuteur Python. `mcp.cjs` exerce le SDK MCP 1.31.0 sur E07/E12; `a2a.cjs` exerce le SDK A2A officiel 1.3.0 par client et serveur JSON-RPC HTTP locaux sur E07/E12; les deux réutilisent l'exécuteur de référence pour isoler le coût du transport. OPA 1.21.4 évalue les règles E03/E08 par requêtes HTTP au moteur. LangGraph 1.5.3 avec `SqliteSaver` exécute un graphe checkpointé sur E05/E06/E07/E10; E06 injecte une panne après un effet journalisé et vérifie la reprise sans duplication. Les cinq familles (LangGraph, A2A, MCP, OPA et JSON Schema) disposent d'une qualification descriptive sur le corpus public, sans test de significativité. Temporal 1.25.0/CLI 1.9.1 exécute E05/E06/E07; sa qualification attend le résultat du run courant. MLIR utilisera `mlir-opt-22` 22.1.2 dans Ubuntu 26.04 sous WSL; les latences de cet environnement Linux sont exclues des comparaisons Windows. Les applications et N/A sont listés dans `../reports/perimetre-baselines.md`.

`gcir_optimized.cjs` est une qualification partielle de C : elle valide chaque enveloppe avec le validateur d'interopérabilité G-CIR, compile/exécute le graphe Omega et applique une fusion des additions adjacentes à E04. Hors E03 (validation G-CIR), les handlers de travail de A sont réutilisés; E04 est le seul cas qui applique la passe de fusion. Ce passage ne mesure donc pas une optimisation générale ou un gain face à A.

Avant de comparer une famille, spécifier l'adaptateur fonctionnellement équivalent, sa version exacte et ses capacités applicables. Marquer `N/A` les métriques hors contrat. Ne pas remplacer les fonctionnalités absentes par des échecs artificiels ni accorder à une condition des outils ou budgets différents.
