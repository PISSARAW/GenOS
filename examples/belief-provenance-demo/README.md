# Belief Provenance Demo

Scenario implemented in this demo:

```text
S0 (no belief)
  -> record tool call db_query on S0                (event E1: ToolRequested)
  -> record tool call completion on S0              (event E1: ToolCompleted, T1)
  -> derive belief B1 from T1 evidence on S0        (event: memory_created)
       B1 └── derived from T1
              └── generated by E1
```

The invariant under test — once a tool output is recorded on the same branch,
a belief can cite it via `--evidence <T1.id>`. The CLI validates the tool
output is present, auto-flips the belief's status to `inferred`, and the new
top-level `genos inspect belief` command renders the provenance tree:

```text
api returns_one yes (confidence=0.90, status=Inferred)
└── derived from db_query (success, <T1.id>)
    └── generated by tool_completed seq=2 branch=<…>
```

The chain is `belief → tool output → event`, all rendered from the snapshot's
own state and a JSONL-backed event lookup filtered to the snapshot's branch.

## What the script does

1. Create agent A and snapshot S0 (no belief yet).
2. Record tool call `db_query` on S0 — emits `ToolRequested` (sequence 1) and
   `ToolCompleted` (sequence 2); appends T1 to `state.tool_outputs` with
   `generating_event_id` pointing at the completion event.
3. Derive belief B1 with `--evidence <T1.id>` — validates T1, flips status to
   `inferred`, links the evidence ref, and emits `memory_created` (sequence 3).
4. Render the inspect tree in text form and assert the literal connectors
   (`derived from`, `generated by`) and labels (`db_query`,
   `tool_completed`) appear.
5. Render the inspect tree in JSON form and assert the structural shape:
   `tree.kind == "belief"`, first child kind `tool_output` with
   `edge == "derived from"`, grandchild kind `event` with
   `edge == "generated by"`.
6. Replay S0's stream — `last_sequence == 3` (T1.requested + T1.completed +
   B1.created).

Every step is a `genos` command: the demo never edits snapshot or event
JSON by hand, so the invariants it proves are the ones the CLI actually
enforces.

### PowerShell (Windows)

```powershell
.\run-demo.ps1
```

### Bash (Linux/macOS)

```bash
./run-demo.sh
```

### What to expect

- The script stops immediately on any assertion failure. The assertions
  live in the script itself, which exits non-zero on a failed `throw`.
- Final output prints `Demo OK: B1 derived from T1 generated by E1` plus
  the snapshot, event, and inspect paths.
- Generated files live under:
  - `.genos/demo/belief-provenance/agent-snapshots.jsonl`
  - `.genos/demo/belief-provenance/agent-events.jsonl` (one `ToolRequested`,
    one `ToolCompleted`, one `memory_created` — all on S0's branch)
  - `.genos/demo/belief-provenance/snapshot-s0.json`
  - `.genos/demo/belief-provenance/inspect-text.txt`
  - `.genos/demo/belief-provenance/inspect.json`

## CLI commands behind the demo

### `snapshot record-tool-call`

Record a tool call on a snapshot's own branch. Emits a `ToolRequested` and
then a `ToolCompleted` (or `ToolFailed`) event for the call, and appends the
resulting `ToolOutputRecord` to `state.tool_outputs` with
`generating_event_id` pointing at the completion event.

```bash
genos snapshot record-tool-call \
  --snapshot snapshot-s0.json \
  --tool-name db_query \
  --input '{"sql":"SELECT 1"}' \
  --output '{"rows":1}' \
  --success true \
  --snapshots agent-snapshots.jsonl --save \
  --events agent-events.jsonl --emit-events
```

### `snapshot set-belief --evidence <T1.id>`

Insert-or-update a `(subject, predicate, object)` belief on a snapshot's own
branch and link one or more recorded tool outputs as evidence. The new
belief's status auto-flips to `inferred` when evidence is supplied and no
explicit `--status` is passed.

```bash
genos snapshot set-belief \
  --snapshot snapshot-s0.json \
  --subject api --predicate returns_one --object yes --confidence 0.9 \
  --evidence <T1.id> \
  --snapshots agent-snapshots.jsonl --save \
  --events agent-events.jsonl --emit-events
```

If an evidence id isn't recorded on this branch, the call fails with
`BeliefError::UnknownEvidence` — `--evidence` always validates.

### `genos inspect belief`

Render a belief's provenance tree: the belief root, its evidence tool
outputs (T1), and the events that produced them (E1). Text mode prints a
human-readable box-drawing tree; JSON/YAML mode emits the structured tree.

```bash
# Text tree
genos inspect belief \
  --snapshot snapshot-s0.json \
  --belief-id <B1.id> \
  --events agent-events.jsonl

# Structured output for tooling
genos inspect belief \
  --snapshot snapshot-s0.json \
  --belief-id <B1.id> \
  --events agent-events.jsonl \
  --format json
```

The `--events` flag points at the JSONL event store; omitting it still
renders the belief and its evidence nodes, but the `generated by` grandchild
shows as a `missing` node rather than the originating event.
