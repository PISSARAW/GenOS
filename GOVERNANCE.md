# Governance

GenOS currently uses a maintainer-led governance model. The repository maintainer is responsible for project direction, releases, security response, contributor access, and final merge decisions.

## Decision-making

Routine changes are decided through pull-request review. Decisions that establish a durable architectural constraint, redefine a core object, or affect multiple subsystems should be documented as an Architecture Decision Record in `docs/2-architecture/adrs/`.

The maintainer aims to seek evidence and contributor input before making consequential decisions. When consensus is not possible, the maintainer makes the final call and records the rationale in the pull request, issue, or ADR.

## Roles

### Contributors

Anyone who reports issues, improves documentation, proposes designs, writes code, reviews changes, or helps other users is a contributor.

### Reviewers

Reviewers are trusted contributors who consistently demonstrate sound technical judgment in part of the project. They may triage issues and provide reviews, but merge access is not implied.

### Maintainers

Maintainers can merge changes and manage releases. They are expected to uphold the Code of Conduct, protect project security, disclose conflicts of interest, review changes within their expertise, and preserve the project's core invariants.

## Becoming a maintainer

Maintainer status is earned through sustained, constructive contributions and reliable review judgment. Existing maintainers nominate and approve new maintainers. Access may be reduced after prolonged inactivity or removed for security, conduct, or trust violations.

## Changes to governance

Governance changes are proposed through a pull request to this file and require explicit maintainer approval.
